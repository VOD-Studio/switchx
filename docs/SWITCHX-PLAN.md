# SwitchX 完整产品与技术方案

> 方案日期：2026-09-24。阶段：设计评审，不是已实现功能说明。
> 目标技术：Rust + Slint，原生桌面；不以网页壳作为正式产品。
> 本次不修改用户的 Codex 配置、凭据或后台进程，不创建产品工程，不提交代码。

## 0. 结论与关键决策

**SwitchX 是面向 Codex 的本地模型控制台：安全切配置、管理上游、统一模型目录，并按所选模型精确路由。**

它不是单纯给 CC Switch 换皮。核心体验应是：

1. 添加 DeepSeek、OpenAI 官方等上游，验证连接与模型能力。
2. 勾选希望在 Codex 中看到的模型，发布一个统一模型目录。
3. 开启路由模式，安全地把 Codex 指向本地 SwitchX。
4. 在 Codex 的模型菜单中选择模型，下一次请求自动去往对应上游。
5. SwitchX 展示实际路由、错误、用量和恢复入口；不要求每次选模型都切一次配置。

**必须先澄清的事实：**

- “OpenAI 官方 API Key”与“ChatGPT 订阅账号中的 Codex”是两个认证、计费和兼容性路径，不能混为一个 provider 模板。[S1][S2]
- 当前 DeepSeek 官方已提供 Codex 的原生 Responses 接入指南，因此 DeepSeek 首选原生链路，不预设必须经过 Chat Completions 转换。[S3]
- Codex 有 `model_catalog_json`；只聚合 `/v1/models` 不等于 Codex 的模型菜单必然出现全部模型。目录文件必须符合目标客户端 schema，并在启动时读取。[S1]
- 已打开的本地 Codex CLI 是 `0.155.0-alpha.16`。它是预发布版本，不把单次在这台机器成功当成稳定版、Desktop、IDE 全部兼容的证明。
- 参考项目是用户提供的 `others/cc-switch`，本次审计基线为提交 `da193d4`，时间 2026-09-23；功能基线不是凭印象猜测的旧版本。

## 1. 范围：如何做到“几乎所有 CC Switch 功能”

“覆盖目标”不等于“首个可运行版本把全部生态一次做完”。以能力清单对齐，按依赖交付，不用一个模糊百分比声称兼容。

| 能力域           | 最终覆盖目标                                                | V1 验收范围                                 | 后续完整覆盖                         |
| ---------------- | ----------------------------------------------------------- | ------------------------------------------- | ------------------------------------ |
| Provider         | 新增、编辑、复制、排序、分组、标签、预设、自定义地址/请求头 | Codex，API Key，官方登录模式区分，连接验证  | 更多 OAuth、平台预设和供应商特殊行为 |
| 配置切换         | 原配置导入、当前配置识别、直连切换、差异预览、恢复          | 必须完整                                    | 多工具联动与团队模板                 |
| 本地代理         | 启停、端口、上游代理、TLS/流式/取消、诊断                   | Codex Responses                             | 其他客户端协议                       |
| 故障保护         | 超时、有限重试、熔断、半开探测、冷却与候选顺序              | 模型级策略，候选必须明确授权                | 更复杂的负载策略与平台优化           |
| 模型管理         | 发现、手动添加、能力元数据、目录发布                        | **跨上游聚合模型目录与模型路由，首版核心**  | 更多目录源与版本兼容包               |
| 用量与费用       | 请求日志、延迟、token、缓存、按模型/上游聚合                | 元数据默认开启，费用明确“估算”              | 官方账单导入/核对、更多统计          |
| MCP              | 导入、启停、编辑、状态、配置同步                            | Codex 所需配置管理；命令不自动执行          | 多客户端同步与更完整工具检验         |
| Skills / Prompts | 来源、安装/卸载、作用域、版本、同步、提示词集合             | Codex，先审阅再安装                         | 市场/跨客户端深度管理                |
| 备份 / 迁移      | 导出、导入、恢复、格式版本、冲突处理                        | 本地与 CC Switch 的可映射部分；凭据重新授权 | 加密 WebDAV 等远端同步               |
| 会话             | 列表、检索、关联客户端、跳转/恢复                           | 首版只读索引与外部打开，不改会话历史        | 更多格式、平台迁移功能               |
| 桌面体验         | 托盘、快捷入口、启动设置、主题、语言、通知                  | 必须完整，减少动态效果                      | 各平台细节完善                       |
| 导入入口         | 粘贴配置、文件导入、预设                                    | 文件与粘贴，预览后应用                      | URI 深链/二维码，始终需确认          |
| 其他 CLI         | Claude Code、Gemini、OpenCode 等                            | 信息模型留兼容余地，首版不假装支持          | 按本地审计清单逐项扩展               |

具体既有能力、源码定位和尚不等价的行为，见 `research/cc-switch-capability-audit.md`。发布时为每项维护 `未开始 / 已实现 / 自动化通过 / 真机通过` 四列。

**明确不做：**自建云账户体系、自己的模型推理平台、插件市场后端、可视化脚本语言、任意流量抓包、默认上传提示词、模拟官方登录网页。高级功能不足时明确显示未支持，不用静默降级掩盖。

## 2. 产品模型：把容易混淆的概念拆开

### 2.1 两种连接模式

**直连模式**

- SwitchX 管配置，不经手推理请求。
- 原生支持该上游协议的 Codex 才能直连；只支持 Chat Completions 的第三方上游不能被伪装成 Responses 直连。
- 切换配置对新启动客户端生效；已有客户端是否重载必须经版本验证，不声称立即切换已有会话。
- 退出 SwitchX 不影响已经配置好的直连。

**路由模式**

- Codex 指向 SwitchX 的 loopback 地址；模型菜单来自 SwitchX 发布的目录。
- 改选已经发布的模型，下一次请求按新的 `model` 精确分发，不重新编辑配置。
- 修改目录、能力或全局认证模式需要重新发布；界面区分“路由已更新”和“客户端待重载”。
- 关闭主窗口继续驻留；完全退出时先选择恢复直连并排空请求，或明确接受客户端暂时不可用。

### 2.2 领域对象

| 对象             | 含义与不变量                                                      |
| ---------------- | ----------------------------------------------------------------- |
| `Provider`       | 上游连接地址、协议族、认证引用、TLS/代理/自定义头策略，不代表模型 |
| `CredentialRef`  | 系统凭据存储中的引用；数据库无上游明文密钥                        |
| `UpstreamModel`  | 某一 provider 真实提供的模型标识与探测记录                        |
| `PublishedModel` | 给 Codex 展示的稳定 ID、名称、能力、prompt 兼容信息和发布状态     |
| `RouteBinding`   | PublishedModel 指向一个主上游与明确候选，而不是反向猜测           |
| `RoutePolicy`    | 超时、并发、重试、熔断、允许的故障切换条件和数据发送范围          |
| `ClientProfile`  | Codex 安装/版本/`CODEX_HOME`/配置目标/连接模式；不等于上游        |
| `Generation`     | 配置与目录版本，关联路由快照、哈希、验证结果                      |
| `SwitchJournal`  | 切换状态机、变更字段、恢复依据，不保存裸认证数据                  |
| `RequestRecord`  | 一次请求的选定模型、实际 provider、路由版本与结果                 |

首版是普通 Rust 数据结构与模块，不为每个名词制造一个 crate、trait 或后台任务。只有实际变化的协议适配和凭据后端需要独立 seam。

### 2.3 模型身份证明与重名

示例映射是方案，不是已发现的真实账号模型：

| Codex 中的名字    | Codex 发来的稳定 ID | 实际上游                                       | 发给上游的 model                                  |
| ----------------- | ------------------- | ---------------------------------------------- | ------------------------------------------------- |
| DeepSeek · Flash  | `sx-ds-flash`       | `provider-deepseek`                            | `deepseek-flash`，启用前重新发现验证              |
| OpenAI · Coding   | `sx-oai-coding`     | `provider-openai-api` 或显式选定的官方账号连接 | 从该连接当前目录选择的真实 ID，不硬编码“最新模型” |
| 我的备用 · Coding | `sx-backup-coding`  | `provider-backup`                              | 备用站真实 ID                                     |

- ID 使用受目标客户端验证的安全字符集合，首版 ASCII 字母、数字、连字符；显示名可中文。
- 显示名、远端 URL、上游密钥可变；公开 ID 不随重命名变化。
- 同名模型来自多个供应商时分别发布，或由用户显式把它们设为一个逻辑模型的候选。
- 不能因为模型名包含 `deepseek`、`gpt` 或 `codex` 就自动选择地址。
- 已发布 ID 不自动重新绑定到不同隐私域；变更需要差异预览。

## 3. 核心增强：目录发布与请求路由

### 3.1 全链路

```text
上游模型发现 / 手动录入
          ↓
能力核查、认证验证、用户选中
          ↓
PublishedModel + RouteBinding + generation
          ├── 版本化 Codex 模型目录文件
          ├── 通用 GET /v1/models
          └── 内存路由快照
                       ↓
Codex 启动 → 读取目录 → 用户 /model 选择 sx-ds-flash
                       ↓
POST loopback/v1/responses { model: "sx-ds-flash", ... }
                       ↓
本地鉴权 → 精确路由 → 能力校验 → 选择认证/协议
                       ↓
POST DeepSeek Responses { model: "deepseek-flash", ... }
                       ↓
原生 SSE / 必需的最小归一化 → Codex
```

选 `sx-oai-coding` 时相同入口分发到所绑定的官方连接。**统一的是入口和菜单，不是把不同供应商的身份、协议、能力和会话状态强行合并。**

### 3.2 不把 `/v1/models` 当成全部答案

两个独立产物同时存在：

1. 通用发现接口：OpenAI-compatible `data[].id`；供 SwitchX 诊断和其他兼容客户端使用。
2. Codex 目录：完整、版本化的 `model_catalog_json`；元数据由目标客户端 schema 与官方供应商模板共同约束。[S1][S3]

需要管理的能力至少包括：工具调用、工具 schema 类型、图片输入、推理档位、推理摘要、上下文/输出限制、并行工具、shell 工具类型、适配后的指令模板、远程压缩/状态续接支持、传输方式。

**这些是内部能力模型，不保证每一项都有同名 Codex 配置字段。**发布器按具体客户端 schema 生成实际字段；不能发明客户端不认识的字段。

目录状态：`草稿 → 可发现 → 能力待验证 → 已验证 → 已发布 → 待重载 / 已确认加载`。简单“连通”不等于工具调用能力验证通过。

目录生成原则：

- 不只写 `id/name`，不照抄一个 GPT 模板给所有模型。
- 根据真实客户端 schema 校验完整结构；`shell_type` 等字段的版本差异必须纳入 fixture。
- 不把 `high/xhigh/max` 当作所有上游共同支持的档位，UI 仅展示已验证交集。
- 不把上游上下文窗口夸大为官方模型窗口；模型指令模板也不能盲目复用。
- 发布到新文件后再更新配置指针，旧版本保留供正在启动或恢复的客户端使用。
- 目录变动默认提示重启/重新加载；只有经过验收的客户端版本才允许显示“已热更新”。
- Desktop 菜单能力要独立检查：DeepSeek 官方说明某些版本仅显示 `Custom`，其他版本才显示可切换模型名；“读取了同一份配置”不是完整模型菜单体验的保证。[S3]
- 最新目录拉取失败时保留上一个有效版本，明确标注陈旧与错误，不能用空目录覆盖。

### 3.3 路由选择顺序

```text
1. 对本地请求做认证与限流
2. 查 exact public_model_id
3. 若请求携带服务器状态引用，校验它绑定的 provider/model/session
4. 取本请求固定的路由 generation
5. 校验请求能力、数据发送许可、目标状态与并发预算
6. 选择主候选；按显式策略尝试被允许的备用候选
7. 使用选定 provider 的认证，替换 model，发送请求
8. 流式转发、取消传播、记录实际去向和终态
```

未知模型返回可诊断的 `unknown_model`；所有候选不可用返回 `no_eligible_upstream`；能力不匹配返回 `unsupported_capability`。不落到一个“默认供应商”蒙混通过。

### 3.4 故障切换语义

- “换地址但同一逻辑模型”与“换成另一个模型”是两种策略，后者需要额外明确授权。
- 候选必须同时满足模型能力、认证和数据区域约束；费用可能变化需展示。
- 不把 `401/403`、余额不足、普通模型参数 `400` 当成无限重试理由；鉴权失效进入需要用户处理的状态。
- `429` 尊重 `Retry-After`；设置总时间预算，而不是多个候选各重试一遍造成长时间卡住。
- 默认只重试能证明可安全重放的请求。请求已发出但无响应的模糊超时也可能已经计费或执行，不能因“还没收到首 token”就判定安全。
- 一旦下游已收到任何不可撤回的流事件，不自动拼接另一供应商的答案。返回明确中断及请求编号。
- 带服务器状态引用的续接不跨 provider 故障切换。
- 原生官方账号请求固定在已选账户，不参与跨账号自动故障切换；用户主动选 DeepSeek 是重新选择模型并重建出站认证，不是拿官方 token 重试到第三方。
- 熔断按 `provider + endpoint/model` 合理分层，避免一个模型参数错误熔断整个供应商；半开只放有限探测。
- 首版使用顺序候选，不做推测请求/双发竞速，避免重复计费。

### 3.5 会话与“直接切换模型”的边界

最低承诺：在已加载的目录中选择另一个模型，**下一次可独立重放的请求**去往正确的上游。

- 新会话切换模型：必须验证。
- 同会话、完整历史可携带的切换：必须用多轮工具对话验证。
- `previous_response_id`、provider 私有压缩项、加密推理项、WebSocket 连接状态不能跨供应商原样转移。
- 有状态续接记录最小的 `response_id → provider / public model / generation` 绑定，限定 TTL；不因此默认缓存整个提示词。
- 新模型与旧会话状态不兼容时明确要求新建会话，或用户选择经验证的无状态重放；不删除历史后假装继续成功。
- 用户停止生成、断网、切页或关闭窗口都不能触发重复工具执行。

### 3.6 协议与传输

**V1 主链路：**Codex Responses → SwitchX → 原生 Responses 上游。

**兼容扩展：**Responses → Chat Completions / Anthropic Messages。它们是真实协议适配器，不是改 URL 和字段名。

适配契约覆盖：`instructions/input`、消息角色、tool 定义、tool call ID、tool result、并行工具、文本与非文本 item、推理字段、usage、finish 状态、错误、SSE 分片与取消。不能表达的能力返回明确错误，禁止静默丢弃图片、工具结果、推理或约束。

流式处理要求：

- 不依赖 TCP chunk 恰好等于一条 SSE；支持跨片 UTF-8、多行 data、CRLF 与 keepalive。
- 保留事件顺序、工具调用 ID、终止语义；未知可透传字段尽量保留。
- 背压、有界缓冲、最大 body/event 限制和取消传播；不等全部答案完成才返回。
- 请求记录区分“连接成功 / HTTP 成功 / 首事件 / 真正完成”，避免把 SSE 中的错误算作成功。
- 原生透传也需要验证 alias 是否影响响应 `model`、instructions、工具类型与客户端行为。
- 首版不承诺 WebSocket；在目标客户端允许的配置中明确关闭，验证能回退到 SSE。不能回退的版本列为不支持。
- `/responses/compact` 等辅助端点必须单独探测和声明；未实现时返回诊断，不能假装主 `/responses` 成功就完整兼容 Codex。

## 4. 官方站点认证：不是一个开关能包办

### A. OpenAI 官方 API Key

这是最直接的稳定首发链路：Key 存系统凭据存储；路由器按选定 provider 注入，绝不复用另一上游的 key。它是 API 计费，不消耗 ChatGPT 订阅额度。[S2]

### B. ChatGPT 订阅账号中的 Codex

这是用户“官方站点”很可能真正想要的能力，不能用 A 冒充交付。设为**明确的首版发布验收门槛**；如果没过，版本标注“API 路由预览版”，不能宣布完整实现需求。

优先验证“Codex 管登录，SwitchX 做本地受控转发”的模式：

1. 用户通过官方 Codex 登录，不伪造登录页面、不抓浏览器 cookie、不把 API Key 当订阅令牌。[S2]
2. 目标版本使用 `requires_openai_auth = true` 的官方认证路径，把该次请求的认证带到已授权的本地路由。该组合需要实测，不是官方对第三方代理的稳定承诺。
3. 增加独立的 loopback 客户端校验信息。若目标客户端只能从配置读取固定自定义头，该本地专用密钥写入权限受限配置，明确它是**本地访问凭据的例外**；不含上游 Key，不写日志、不导出，绝不转发。
4. 请求选官方模型时，仅转发到锁定的官方上游目标；需要的 account header 也只在这条路径使用。使用显式构造的头集合，不复用整包客户端头。
5. 请求选 DeepSeek 时，丢弃所有 OpenAI 认证和账号头，使用 DeepSeek 自己的 Key。
6. 续期责任优先保持在 Codex 一侧，验证真正的 token 过期场景。未经授权不复制 `auth.json`，不另开争抢 refresh token 的轮询器。
7. 如果当前 Codex 的提供商/认证选择使这种组合不能稳定工作，停止声称支持；再评估用户明确同意的官方认证集成，而不是偷偷使用未说明的登录方案。

账号关联、并发会话、登录失效、账户切换、模型可见性、额外头、官方协议变化都进入独立兼容测试。可能依赖内部变化的部分隔离在单个官方连接实现中，不能散落到所有请求处理路径。

### 本地凭据 helper 路径

在支持 `model_providers.<id>.auth.command` 的目标客户端上，**API-only 路由**可以从 SwitchX helper 取短作用域本地令牌，避免给每个 shell 手工设置环境变量。[S1]

`auth` 与 `requires_openai_auth`、`env_key`、`experimental_bearer_token` 在同一 provider 配置中互斥，不能同时启用。[S1] 旧客户端的后备选择必须显式展示：受控启动环境或本地专用 token，不能生成指向一个用户尚未设置的 `env_key` 然后宣称开箱即用。

## 5. 配置安全：切换本身必须可靠

### 5.1 管理范围

优先修改当前选择所必需的字段，如 `model_provider`、`model`、本应用的 provider 表、`model_catalog_json` 和实际需要的能力配置。完整字段集按客户端适配器定义，不覆盖整个 `config.toml`。

- 尊重 `CODEX_HOME`，支持多个安装/配置目录；不硬编码只有 `~/.codex`。
- 使用 `toml_edit` 保存无关注释、表与字段。
- 默认保留 MCP、项目可信度、sandbox/approval、安全要求、用户指令、插件、历史设置和非 SwitchX provider。
- 不通过修改组织托管策略或安全配置“让路由能用”。
- 不因退出路由就删除官方登录态；`auth.json` 默认不是 SwitchX 管理文件。

### 5.2 事务流程

```text
Idle
 → Inspect（识别客户端、锁定目标、读当前哈希）
 → Prepare（计算最小差异、生成目录、准备候选路由）
 → Validate（结构、能力、loopback 健康与鉴权）
 → Snapshot（需要恢复的字段、加密的敏感原始快照）
 → Commit（目录先落盘，再原子替换配置指针）
 → AppliedAwaitingClientReload
 → Verified（实际客户端请求确认了 generation）

任一步失败 → 保留旧有效配置 / 依据 journal 恢复
外部文件变化 → Conflict，需要预览与决策，不强写
```

重要实现细节：

- 多文件不能靠几个 `rename` 获得跨文件事务。使用不可变目录版本，最后原子更新配置，并持久化 journal。
- 临时文件放同一文件系统；flush/sync、权限和 replace 行为按平台验证。
- 提交前比较原始哈希；其他写入者变化则重读并重新生成差异。文件监听只提醒冲突，不持续“纠正”外部程序。
- 退出恢复用三方比较，只撤回仍为本应用写入值的受管字段；不覆盖用户在路由期间新增的内容。
- 旧快照中的明文 key 属于敏感数据，即使来自用户原配置，也需加密保存或不持久化。
- 崩溃后下次启动根据 journal 恢复；不能声称进程死亡时仍有代码自动恢复配置。
- 同一时间只允许一个 SwitchX 管理同一个配置目标。提示 CC Switch/其他配置工具冲突，但不擅自停用对方。

### 5.3 生命周期

| 动作               | 产品行为                                                 |
| ------------------ | -------------------------------------------------------- |
| 关闭主窗口         | 默认隐藏到托盘，首次说明路由仍运行                       |
| 完全退出且正在路由 | 提示恢复直连；停止新请求、限时排空、恢复受管配置         |
| 用户强制退出       | 显示可复制恢复步骤；下次启动处理 journal，不伪造后台自愈 |
| 开机启动           | 需要用户开启；按平台注册，不默认提权                     |
| 端口被占用         | 停止切换并说明；只有同步发布新地址后才能改端口           |
| 睡眠/唤醒          | 重新检查网络、凭据和上游连接，不丢失配置所有权           |
| 外部修改配置       | 黄色状态提醒、差异预览；暂停写入，不形成 watcher 对抗    |
| 客户端版本升级     | 目录兼容再验证；保留上次可用目录与明确降级入口           |

## 6. 架构与目录组织

### 6.1 一进程，两个执行域

```text
Slint UI 主线程
  AppWindow / 页面 / ViewModel / 用户操作
                │ typed command / result / event
                ▼
Rust 应用逻辑 + Tokio runtime
  Provider 管理     目录发布       Codex 配置事务
  凭据访问          SQLite         路由快照
                │
                ▼
Axum loopback ingress → 路由决策 → 协议实现 → Reqwest 上游连接
```

- Slint event loop 留在主线程，后台任务不直接修改 UI；批量把状态投递回事件循环。
- UI 只处理展示和意图；不在点击回调里做磁盘、DNS、数据库大查询或网络等待。
- SQLite 初期采用一个串行访问执行域，避免在网络流任务中阻塞；简单业务不先引入数据库 ORM。
- 请求使用开始时的不可变路由快照。编辑 provider 不会把一个正在输出的请求中途切到别处。
- 高频日志/统计批量更新，活跃视图使用有界模型；不因每个 token 重建整个列表。
- 一个 executable + 内部模块足够首版。需要隔离重启或跨进程共享时再拆独立 router 进程，不提前承担 IPC/升级协调成本。

### 6.2 建议工程形态（尚未创建）

```text
  config/           Codex 识别、差异、事务、恢复
  catalog/          发现、能力校验、目录生成
  routing/          Axum、路由策略、流式与生命周期
  providers/        原生 Responses、官方账号、兼容协议

  desktop/          托盘、主题、窗口、系统集成

```

当测试或复用确实需要时再拆 `switchx-core`，不在设计阶段创建十几个只有转发函数的小 crate。

### 6.3 存储

建议表：`providers`、`upstream_models`、`published_models`、`route_bindings`、`client_profiles`、`config_generations`、`switch_journal`、`request_records`、`usage_rollups`、`preferences`、`schema_migrations`。

- macOS 默认使用应用支持目录；Windows/Linux 用平台约定目录，通过统一路径模块解析。
- 运行配置、日志、数据库、缓存分目录；不把一切塞到 Codex 的目录。
- Codex 目录只放必要的版本化 catalog 与明确受管的配置表。
- 模型发现使用限时缓存；手工刷新、最后成功时间、错误时间分别保存。
- 请求正文默认不落盘，调试捕获需显式开启、限时、大小上限、自动清理和导出前脱敏。
- 费用依据带版本/币种的价目表估算；缓存 token 单独计价。订阅账号不伪装成 API 实付账单。
- 数据库迁移可回退备份，写 schema version；导入未知版本先检查，不直接覆盖。

### 6.4 最新依赖与版本选择

完整在线核查结果、精确版本、MSRV/许可证注意事项见 `research/dependencies-and-slint.md`。该表是本轮可核实的注册表状态，不是永远成立的“最新”。

选型原则：

1. Stable 优先；不因为版本号更大就使用 prerelease。
2. `slint` 与 `slint-build` 同版本；正式开发提交 `Cargo.lock`，对兼容敏感项精确锁定。
3. 最新单包版本不代表整个组合已编译。先建立最小 Slint + Tokio + Axum + TLS + Keychain 的集成骨架，再扩界面。
4. 优先少依赖：标准库和既有库能完成的差异、导出、缓存，不再引入新的框架。
5. TLS 证书、系统代理和企业 CA 需要按平台实测，不以禁用校验解决。
6. Slint 1.18.1 已有内建 `SystemTrayIcon`，首选它，不默认叠加 `tray-icon/muda`。事件循环、关闭窗口驻留和系统菜单仍做 proof-of-concept；内建托盘不足时才引入替代依赖。
7. Slint 授权方式与 CC Switch MIT 复用要求在发布前单列审核，不把“Rust 生态”当成可忽略许可证。

当前核实的核心稳定版基线：Rust **1.98.1**；`slint/slint-build` **1.18.1**；`tokio` **1.53.1**；`axum` **0.8.9**；`reqwest` **0.13.5**；`rusqlite` **0.40.2**；`toml_edit` **0.25.15+spec-1.1.0**；`keyring` **4.2.0**。完整 18 项版本、发布日期、MSRV 见依赖研究。

渲染初始验证选择 Winit + Skia，与 FemtoVG 对照小字号中文、阴影和内存。Skia 是候选，不是已经实测选出的最优解；实验性 renderer 不做首发默认。减少动态效果先提供应用内设置，跟随系统的跨平台桥接另行验证，不声称 Slint 自动处理全部平台设置。

## 7. 视觉方向：Quiet Circuit / 静谧回路

不是泛用后台模板，不是大量发光玻璃卡片。关键词：**安静、精确、有呼吸感、原生、专业但不拥挤。**

已有可点击视觉稿：`design/switchx-preview.html`。它是独立设计演示，不是实际 Slint 实现，不连网络、不读账号、不修改配置。所有模型、状态、请求均标明演示。

### 7.1 品牌

- 名称：`switchx`，小写字标，x 为轻微强调。
- 标记：两条交叉但有清晰去向的路径，表达切换与路由，不使用夸张电路板背景。
- 宣传句：“一个 Codex，自由连接你信任的每一个模型。”
- 首页主标题：“模型，各就各位。”
- 精确信息优先于营销文案；错误文案给原因、影响、下一步，不堆“发生未知错误”。

### 7.4 页面完整清单

**首次运行**：选择检测到的 Codex → 检查配置来源 → 只读导入 → 凭据授权 → 添加/验证上游 → 选择模型 → 差异预览 → 激活。允许跳过并保留现状；检测已有管理工具时解释冲突。

**总览**：当前客户端、直连/路由、真实健康状态、路由示意、上游简卡、已发布模型、最近错误、待重载提醒。拒绝一屏十几个没意义的统计卡。

**上游供应商**：卡片/紧凑列表、搜索标签、排序、连接/模型/认证三种状态；详情抽屉包含连接、认证、模型、诊断、高级五组。新增采用三步向导，不一次铺开所有参数。

**模型路由**：左列为公开模型，右侧为实际绑定与候选；直观的映射表为主，拓扑图仅作只读说明。显示 public ID、上游真实 ID、协议、能力与验证状态，支持发布预览、撤销、候选顺序、测试路由。首版不做拖线编程工具。

**请求与用量**：虚拟化列表、时间/模型/供应商/状态筛选；详情显示 request ID、实际去向、所用 generation、TTFT/总时长、usage、重试/熔断原因。默认无正文；暂停自动滚动，日志不能抢滚动位置。

**MCP / Skills / Prompts**：列表分组、scope、来源、启停、预览差异、失败详情。脚本与 MCP 命令有执行提示，导入不等于执行。

**配置与恢复**：当前生效配置与来源、每次变更的字段 diff、备份、恢复、冲突。大段配置用只读预览+高级编辑入口，首版不自建复杂 IDE。

**会话**：后续导航入口或工具分组，首版只读列出与外部打开；重命名/删除/迁移作为单独授权动作。

**设置**：主题/语言/动效、托盘/启动、端口/代理/TLS、日志保留、凭据、安全、目录版本、迁移与更新。

**托盘菜单**：当前模式与客户端、最近常用直连配置、路由状态、打开主窗口、恢复配置、退出。不在每次展开时重新写配置。

### 7.5 状态设计不能缺省

每个主要页面必须有：首次空态、加载、部分数据、完全失败、离线缓存、无权限、认证过期、编辑未保存、应用中、冲突、成功待客户端重载。

具体示例：

- “目录已发布，当前 Codex 会话尚未确认加载”与“所有模型已生效”不是同一状态。
- “服务器在运行”与“DeepSeek 工具调用验证通过”不是同一状态。
- “官方账号登录失效”给重新官方登录入口，不给无意义的循环重试。
- 删除被路由使用的 provider 先展示关联模型并要求重新绑定，不能留悬空 ID。

## 8. 动效规格：优雅来自节制

Slint 使用属性动画、状态与过渡等原生机制；浏览器设计稿的 CSS 仅表达视觉意图，不要求正式产品嵌入浏览器。[依赖研究]

| 交互        | 动作                                  | 时长 / 节奏         | 禁止事项                       |
| ----------- | ------------------------------------- | ------------------- | ------------------------------ |
| 按钮 hover  | 背景/边框轻微变化                     | 100–140ms           | 不扩大布局                     |
| 按钮按压    | 0.98 视觉缩放或轻微 inset             | 70–100ms            | 不抖动文字                     |
| 导航切换    | 选中背景移动；内容 opacity + 6px 位移 | 180–220ms，ease-out | 不整屏旋转/弹跳                |
| 直连 ↔ 路由 | 分段滑块 + 状态文字渐变               | 200ms               | 动画结束不等于实际切换成功     |
| 详情抽屉    | 20–30px 位移 + opacity                | 220–260ms           | 不长距离飞入                   |
| 卡片增删    | 短淡入/淡出，稳定列表位置             | 160–200ms           | 不因日志刷新反复播放           |
| 路由请求    | 只对当前选中的路径短暂显示光点        | 600–900ms，有限次数 | 不开永久流光，不显示未发生流量 |
| 状态变化    | 色彩与文案短过渡                      | 120–180ms           | 不连续呼吸制造假健康           |
| Toast       | 8px 位移 + opacity                    | 150–180ms           | 不能只靠 toast 展示严重错误    |
| 主题切换    | 简短交叉过渡或直接切换                | ≤180ms              | 不强求昂贵整窗模糊             |

动效可被中途打断，快速重复操作只落到最新目标状态，不排成长队。减少动态效果开启时取消移动/缩放和路径动画，仅保留必要状态更新。

性能目标是验收标准，不是已经测得的成绩：60Hz 设备 UI 帧预算约 16.7ms；网络请求不阻塞主线程；应用空闲时没有无意义动画和高频唤醒。渲染器选择依据目标机器帧时间、内存、文字与阴影表现，不提前承诺全平台 GPU 高特效。

键盘体验：侧栏可导航，焦点清晰，抽屉管理焦点与 Esc 返回；主要操作有平台习惯快捷键。屏幕阅读器、中文 IME、缩放、系统主题变化都做真机检查，不仅依赖截图好看。

## 9. 安全与隐私

- 路由默认只绑定 `127.0.0.1`；IPv6 loopback 为单独明确支持，不监听 `0.0.0.0`。
- loopback 不是鉴权：使用不可猜的本地凭据，校验 Host，拒绝意外 Origin/CORS；不可依赖浏览器不会访问本地端口。
- 健康接口只返回最少信息；管理命令通过应用内通道，不暴露无认证管理 HTTP。
- 请求的 Authorization、cookie、account header、代理认证、路由令牌均不进入日志、URL或诊断导出。
- 出站头采用白名单构造，拒绝把 Codex 官方账号 token 发到 DeepSeek 或自定义站。
- Provider 目标只来自用户配置的已批准地址；不接受请求 body 自带任意转发 URL。
- TLS 验证默认开启；HTTP 仅默认允许 loopback。自定义局域网/企业目标显式授权，重定向不得携带认证跨域。
- 超时、连接数、body/SSE 大小、并发数有界；防止本地请求把内存撑爆。
- 凭据存储不可用时失败关闭并解释原因，不静默回退明文 SQLite。
- 导入包限制大小、路径、符号链接与解压穿越；深链只打开待审阅表单，不自动写配置或执行命令。
- 远端同步默认不包含凭据；若未来同步 secrets，需独立端到端加密设计，不能以“WebDAV 是 HTTPS”代替。
- 更新需要校验发布来源/签名，macOS 签名与 notarization、Windows 签名、Linux 包渠道分别处理。
- 遥测默认关闭；用户可导出脱敏诊断。发布记录哪些数据从哪台上游实际发送过。

## 10. CC Switch 复用与迁移策略

- 把本地源码作为行为和测试参考，不把 Tauri/React UI 硬塞到 Slint。
- 先评估可独立使用的纯 Rust 逻辑；带全局状态、Tauri command、数据库 schema 假设的代码不盲目复制。
- 复用时保留适用 MIT attribution/许可文件。改写并不自动解除来源义务；本方案不复制第三方资源和商标。[本地 LICENSE]
- 导入明确区分：连接资料、模型映射、MCP、prompts、skills 引用、应用偏好、凭据。
- 不能等价映射的认证、脚本、协议参数出具报告；不静默忽略字段。
- 首次迁移为只读导入、预览、重新验证、用户确认后切换；不删除原应用数据。
- 迁移完成显示“已导入数据”，真实 Codex 请求验证通过后才能显示“迁移已验收”。
