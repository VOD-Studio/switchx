## UI 编译隔离

`crates/switchx-ui/` 只包含 Slint 构建脚本和生成类型。它编译根目录的 `ui/app.slint`，并继续跟踪导入的 Slint 文件和资源。业务库用 `pub use switchx_ui as ui` 保留 `switchx::ui` 接口，主程序、集成测试及预览不需要修改调用路径。

UI crate 不依赖业务库，没有独立单元测试或文档测试入口；现有业务测试、共享控件测试和完整 UI 集成测试全部保留。因此 workspace 测试不会为无测试的生成代码再创建一份 UI 测试 harness。

workspace 的默认成员仍是根应用，所有成员共享 `Cargo.lock` 和 `target/`。没有升级依赖：锁文件只迁移 `slint-build` 的归属并增加本地 `switchx-ui` 包。

## 复用和变更跟踪

本轮主机使用 Rust / Cargo 1.99.0、Slint 1.18.1。先预热同一条 `cargo check --locked --offline --lib -v`，再更新时间戳触发重新检查；源文件内容不变，检查后恢复原时间戳。

| 情形 | 观测 |
|---|---|
| 拆分前，业务文件 `src/requests.rs` 变动 | 根库重新检查，单次墙钟耗时 9.05 秒 |
| 拆分后，同一业务文件变动 | 根库重新检查，单次墙钟耗时 1.87 秒；`switchx-ui` 为 Fresh，未启动 UI 的 rustc |
| 拆分后，`ui/tokens.slint` 变动 | UI 构建脚本重新生成代码，UI crate 启动一次 rustc，根库随后重新检查 |

业务检查前后，10 份 UI 相关编译产物及生成代码的时间戳和大小全部保持一致。UI 源文件检查确认生成文件的时间戳更新。

这验证的是编译单元复用和 UI 变更跟踪。耗时来自单次本机采样，并且源文件只改变了时间戳；不代表任意实际代码改动的稳定加速比例，也不是冷构建或内存对照结果。
