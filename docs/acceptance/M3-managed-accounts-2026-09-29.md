# M3 多账号保存检查（2026-09-29）

本批按用户要求参考本地 CC Switch `846de29` 的账号保存方式。SwitchX 将 ChatGPT OAuth 账号保存在数据目录的 `codex_oauth_auth.json`，API Key 与本地路由令牌仍在系统凭据库。该批检查使用临时目录、合成 JWT 和本地假上游，没有读取用户账号，也没有真实官方登录或模型调用。

## 行为

- 设备码登录与当前文件登录导入可保存多个账号。同工作区、同用户重新登录会更新原记录，保留 ID、默认选择和绑定。
- 设默认不改当前登录。使用指定或默认账号会先恢复受管配置，再写完整 Codex 文件登录；目标设置为 `cli_auth_credentials_store = "file"`，其余配置保留。
- 账号库仅保存 refresh token、ID token 和账号资料；access token 缓存在内存。账号库、原生登录及归属标记采用原子替换，Unix 凭据文件为 `0600`。
- 归属由本地账号 ID、工作区与 JWT 用户身份一起确定。只有属于同账号的新原生续期结果会被采纳；旧代际不能覆盖新凭据，外部文件变化不能被静默覆盖。
- 路由使用绑定账号的认证与工作区，忽略客户端另带的官方认证。API 路由仍只注入自己的 Key。删除绑定账号后请求失败，不回退到其他账号。
- 预览不切换账号；保存账号的路由要求 CLI 返回工作区路由资料。认证等待与模型请求共享超时预算，停止路由会取消在途认证等待。
