# M2 macOS 验收记录 · 2026-09-28

## 环境与范围

- macOS 27.0，arm64；Rust + Slint 1.18.1，本机未签名调试 bundle。
- 目标客户端：Codex CLI 0.156.1。
- 真实上游：DeepSeek，`https://api.deepseek.com`，模型 `deepseek-flash`。
- SwitchX 数据目录与目标 `CODEX_HOME` 均为新建的独立临时目录。真实 Key 由用户在原生安全输入框填写，保存到系统钥匙串；测试只发送合成提示词与合成文件内容。
- 本轮未修改用户日常 Codex 配置，未读取其 `auth.json`，未将 Key、账号资料或测试配置写入仓库。

真实文件工具和第二轮回答来自真实 DeepSeek 请求；单元测试与路由集成测试使用本地 mock。中文输入法结果来自用户实际操作确认，桌面自动化未观察系统候选窗口。系统菜单栏访问超时，因此托盘验收需用户实际点击，进程驻留单独记录。

首轮托盘组合操作的回复为“没问题，退出了”，落盘核对却观察到直连字段与 journal 均保留，无法据此判定恢复成功或确定失败原因。随后直接点击窗口“恢复原配置”，界面报告成功；配置全文等于原夹具加验收期间新增的外部注释，生成的 provider 与 journal 均已移除。重新应用后，用户单独执行托盘恢复，原生页面与文件检查均通过。本轮未复现恢复引擎错误，未为该现象修改产品代码；组合操作的首次结果保留在记录中。

## 自动化验证与复跑

以下检查已通过：

```sh
sh scripts/bundle-macos.sh
cargo test --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
cargo fmt --all -- --check
```

`cargo test --locked --all-targets` 共通过 30 个测试，不执行真实模型调用。新增的探针判定测试要求同时出现完整轮次和精确的助手回答，工具输出或未完成轮次不算成功。

真实直连探针复跑方式：先在隔离 SwitchX 数据目录保存测试上游，再以其 ID 运行：

```sh
cargo build --locked --bin switchx
cargo run --locked --example direct_live_probe -- /absolute/switchx-data PROVIDER_ID
```

探针创建自己的临时配置目录，从钥匙串读取已保存的引用，不接管日常配置。它会产生真实、可能计费的调用；正常结束恢复并清理临时配置，恢复失败或冲突时保留文件供检查。保存的上游与钥匙串条目仍由 SwitchX 管理。

## 尚未覆盖

本轮结果限定为上述 DeepSeek 模型、CLI 版本与 macOS 环境。OpenAI 官方 API、ChatGPT 官方上游与认证续期/失效、Desktop/IDE、取消、跨模型会话及 Windows/Linux 未在本轮验收。路由模式与目录发布的桌面接入属于 M3，不由直连成功推导。
