# M3 首批验收 · 模型目录与 API 路由

## 环境与范围

- macOS arm64，Rust + Slint 1.18.1，本地未签名调试 bundle。
- Codex CLI 0.156.1；CLI 目录检查使用新建的临时配置目录和固定 loopback 地址。
- 两个本地假上游，均暴露 `shared-model`，分别使用独立合成凭据。能力资料来自标为 synthetic 的测试夹具。
- 所有路由请求、模型资料导入、配置切换和恢复验收都使用隔离数据目录与 Codex 配置目录，没有真实上游请求或计费。

这些结果没有把合成模型的能力声明当成真实供应商能力。CLI 的成功判定要求退出成功、`turn.completed` 和准确的助手回答；文件工具输出单独核对。

本轮自动化共 37 项通过，Clippy、Rust/Slint 格式检查与 macOS bundle 构建通过。

退出回归曾发现 Slint 的默认 macOS 退出菜单直接终止进程，跳过事件循环之后的恢复；`--desktop-recovery` 加 Command-Q 能稳定报出 `desktop exited before restoring its route configuration`。现在 AppKit 的退出请求接入同一恢复队列，先取消系统终止，待恢复成功后结束事件循环。复测覆盖待恢复启动和活动路由退出。页面跳转也不再清除刚产生的冲突提示。首次失败遗留的合成测试凭据与目录已清理。

## 复跑

```sh
cargo test --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
make format-check
cargo build --locked --bin switchx
cargo run --locked --example routed_cli_probe
```

`SWITCHX_CODEX_CLI` 可设为待验证 CLI 的绝对程序路径。原生 UI 夹具使用 `routed_cli_probe --desktop`；可通过 `SWITCHX_DESKTOP_BINARY` 指向构建后的 bundle 可执行文件。`--desktop-recovery` 直接准备一份待恢复配置，用 Command-Q 检查退出恢复；退出后先核对原配置及 journal，再进行夹具清理，清理不能掩盖应用退出失败。探针创建并清理自己的合成凭据和临时数据；恢复失败会保留目录供检查。

## 当前边界

本轮交付为 M3 第一批，UI 标为“API 路由预览版”。每个上游连接发布一个模型，修改绑定前需要恢复配置。普通关闭窗口可驻留；强杀时无法执行恢复，下次启动读取 journal 并提示恢复，不能自动继续旧路由。

首批验收时，候选故障切换、请求记录及 SSE 完成状态识别尚未实现。请求记录已在[后续批次](M3-requests-2026-09-28.md)补齐。ChatGPT 订阅官方上游与续期、真实 DeepSeek ↔ 官方切换、同会话跨模型历史、Desktop/IDE、远端压缩、WebSocket 和其他平台尚未由本轮验证。

目录加载和 helper 配置以 [Codex 官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference) 为依据；目标 CLI 在隔离目录解析完整文件，随后仍需针对真实供应商验证工具与会话能力。

macOS 退出使用 [AppKit 的 applicationShouldTerminate 回调](https://developer.apple.com/documentation/appkit/nsapplicationdelegate/applicationshouldterminate(_:))，通过已有依赖 `objc2` 为当前 Slint/Winit delegate 补充该可选方法；不会替换已有实现。升级 Slint/Winit 后需重新验收此平台接入。
