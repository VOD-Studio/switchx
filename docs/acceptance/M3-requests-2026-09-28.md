# M3 请求记录与完成状态验收

## 范围

2026-09-28，macOS arm64、Slint 1.18.1、本机 Codex CLI `0.158.0-alpha.2.1`。请求验收使用本地假上游、临时 SQLite、独立 `CODEX_HOME` 和合成凭据。没有真实模型调用或计费，没有修改用户的 Codex 配置或读取登录数据、上游 Key。

| 检查 | 证据与结果 |
| --- | --- |
| 数据库迁移与持久化 | v1/v2/v3 自动升级至 v4；请求重开后可读，按时间倒序限量读取，删除上游后历史仍保留 |

| 显式失败 | HTTP 429、SSE `error`/`response.failed`/`response.incomplete`、JSON 错误均记录失败；错误文本不会写进数据库 |
| 中断与取消 | 本地 HTTP 集成覆盖正常 EOF 缺终态、上游传输错误、响应头之前取消、输出中取消、5 秒排空后停止；终态与错误码不同，没有重放 |
| 精确映射与计时 | 记录公开模型、provider ID、实际模型、目录 generation、HTTP 状态、响应头及首事件时间和总耗时；响应头包含可对应的请求 ID |

| 隔离 CLI | Alpha 工具调用及工具结果、Beta 回答共三次请求，数据库均为正常完成，模型/上游映射、路由版本与首事件计时正确；恢复后清理所有探针凭据与文件 |

自动化共 45 项通过；Clippy、Rust/Slint 格式检查、macOS 调试 bundle 构建通过。CLI 验证走生产 `RouteSession`，UI 记录展示检查使用直接填入临时数据库的合成记录，二者证据不混用。

## 边界

- 本轮仅提供元数据记录和终态识别，不包含 token/费用统计、筛选导出、清理策略、候选故障切换或真实供应商验收。
- “用户取消 / 客户端断开”描述可观测的下游释放，不能区分用户主动取消与下游网络故障。路由停止造成的截断记录为流中断。
- 计时截止首次明确终态；完成表示收到上游完成信号，不证明客户端已处理全部输出。首事件计时不是 TTFT。
- 仅记录通过本地鉴权并进入 Responses 处理器的请求；记录在终态落盘，强杀时尚未结束的请求可能无记录。数据库写入失败不会把请求误记为成功保存。
- 流式完成事件允许省略可选的嵌套 status；若存在相互矛盾的状态或错误，不判成功。非流式 JSON 必须明确声明 completed。

事件边界遵循 [WHATWG SSE 解释规则](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation)。完成事件与错误事件参考 [OpenAI 流式 Responses 文档](https://developers.openai.com/api/docs/guides/streaming-responses)，可选嵌套状态参考 [官方 SDK 的 Response 类型](https://github.com/openai/openai-python/blob/main/src/openai/types/responses/response.py)。这些协议依据不替代对真实上游的验证。
