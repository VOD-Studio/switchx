# M3 模型切换后恢复检查

2026-09-29，macOS arm64，本机 Codex CLI `0.158.0-alpha.2.1`。

## 问题与修复

Codex 的模型选择会改写 `config.toml` 的 `model`。此前恢复只接受发布时的默认模型，将切换到同一发布目录中的其他模型也判为外部冲突；其他字段可能已经恢复，但 SwitchX 模型 ID、恢复记录和本地令牌仍保留。

恢复现在接受本次发布的模型选择，并恢复开启路由前的模型；原配置没有 `model` 时删除该字段。新 journal 保存公开模型 ID 集合，旧 journal 使用原发布目录识别。路由字段必须仍是本次发布值或已恢复的原值；目录外模型、外部路由修改和非字符串字段继续保留并报告冲突。配置注释和未受管设置继续保留。

| HTTP 夹具 | 各上游使用独立合法 `session-id`，匹配当前持久会话保护；不放宽生产路由鉴权或会话约束 |

HTTP-only 首轮夹具没有发送当前路由要求的会话标识，提前被会话保护拒绝。补齐独立 UUID 后复跑；完整 CLI 探针使用 Codex 原生会话标识。

并行回归曾在重复恢复时遇到短暂锁竞争。独立 fork 夹具复现：仅关闭父进程句柄时，子进程仍持有同一文件锁。共用配置锁现在在作用域结束时显式解锁，直连与路由复用该释放逻辑；其他进程实际持锁时仍拒绝切换。

## 当前恢复记录

先在权限受限的临时副本中复用生产 `RouteSession::restore`，确认仅 `model` 需要恢复，其他配置语义保持；副本中的合成本地令牌和 journal 清理成功，源文件未变化。

实际处理前核对配置和 journal 快照未变化、旧调试进程没有已建立的 TCP 连接。关闭旧进程后，通过相同生产入口完成恢复：模型回到开启路由前的 `gpt-6-sol`，原端口释放，journal 与本次本地令牌移除。上游、模型、会话和请求记录条数保持；原生登录文件及私有账号文件的文件签名保持。未打开原始认证编辑器或输出认证内容。临时副本、私有检查点和一次性恢复包装已清理。

更新后的调试包重新打开，原生模型路由页显示“路由未启用”，恢复和启动按钮禁用，未再显示 `model` 恢复冲突。

## 复跑

```sh
make check
cargo build --locked --bin switchx --example routed_cli_probe
cargo run --locked --example routed_cli_probe
cargo run --locked --example routed_cli_probe -- --http-only
sh scripts/bundle-macos.sh
```

自动化及 CLI 请求使用临时目录、合成凭据与本地假上游。现有配置恢复不包含真实供应商模型请求、登录或续期验收。
